# 計算ロジック

(rounding-employee)=
## 端数処理 — 社員側「50 銭超切上げ」

協会けんぽの公式保険料額表(東京支部)の注釈より:

> ① 事業主が、給与から被保険者負担分を控除する場合、被保険者負担分の端数が **50 銭以下** の場合は **切り捨て**、**50 銭を超える** 場合は **切り上げて 1 円** となります。

これを Excel 数式で表現:

```{code-block} text
=INT(全額/2) + IF(MOD(全額,2)>1, 1, 0)
```

### なぜこの形か

- `全額/2` の整数部分は `INT(全額/2)` で取得。
- 端数部分は `MOD(全額,2)/2` で 0〜0.999... の値になる。
- 端数が **50 銭超** ⇔ `MOD(全額,2) > 1`(因数 2 倍した値で 1 を超えるか)。

### 動作例

```{list-table}
:header-rows: 1

* - 全額
  - INT(全額/2)
  - MOD(全額,2)
  - >1?
  - 社員側
  - 説明
* - 10,093.6
  - 5,046
  - 1.6
  - YES
  - **5,047**
  - 端数 0.8 円 → 50 銭超 → 切上げ
* - 16,104
  - 8,052
  - 0
  - NO
  - **8,052**
  - 端数なし
* - 10,094
  - 5,047
  - 0
  - NO
  - **5,047**
  - 偶数なのでぴったり
* - 10,095
  - 5,047
  - 1
  - NO
  - **5,047**
  - 端数 0.5 円ちょうど → **切捨て**(50 銭以下に含まれる)
```

最後の例(10,095 → 5,047)に注意。`ROUND` 関数を使うと `5,048` になるため使えません。

```{warning}
被保険者が現金で事業主に支払う場合のルール(50 銭未満切捨て・50 銭以上切上げ)とは微妙に違います。本ブックは「給与控除」前提なので前者を採用しています。
```

## 事業主側 — 残額方式

事業主側を社員と同じ式で出して 2 倍すると、合計が `ROUNDDOWN(全額)` を超えるケースがあります。例えば全額 10,093.6 のとき、両側 5,047 にすると合計 10,094 で **+1 円**。

そこで:

```{code-block} text
事業主側 = ROUNDDOWN(全額, 0) - 社員側
```

これにより、$\text{社員} + \text{事業主} = \mathrm{ROUNDDOWN}(\text{全額})$ が必ず成立し、月次計算 Z 列(納付額) = 各保険料の `ROUNDDOWN(全額)` 合計、すなわち年金事務所が出す通知額と一致します。

(kaigo-auto-judgment)=
## 介護該当の自動判定

### 法的境界

```{list-table}
:header-rows: 1

* - イベント
  - 介護該当開始/終了月
* - 40 歳到達
  - 誕生日の前日が属する月から **介護料率を加算**
* - 65 歳到達
  - 誕生日の前日が属する月から **介護料率を停止**(被保険者カテゴリが 1 号に切替)
```

「誕生日の前日が属する月」がポイントで、4 月 1 日生まれは 3 月から、4 月 2 日生まれは 4 月から該当開始です。

### 数式

```{code-block} text
:caption: D列(介護該当)の式

=IF(設定!$B$3="", FALSE,
   AND(
     EOMONTH(DATE(A2,B2,1),0) >= DATE(YEAR(設定!$B$3)+40, MONTH(設定!$B$3), DAY(設定!$B$3)) - 1,
     EOMONTH(DATE(A2,B2,1),0) <  DATE(YEAR(設定!$B$3)+65, MONTH(設定!$B$3), DAY(設定!$B$3)) - 1
   )
)
```

ロジック:

- 対象月の月末日 `EOMONTH(DATE(年,月,1),0)` が
- **40 歳誕生日前日 ≦ 月末日 < 65 歳誕生日前日**

の範囲に入っているかで判定。

### 検証例(生年月日 1986/4/15)

```{list-table}
:header-rows: 1

* - 対象行
  - 介護該当
  - 理由
* - 2026/3
  - FALSE
  - 月末 2026/3/31 < 40 歳前日 2026/4/14
* - 2026/4
  - **TRUE**
  - 月末 2026/4/30 ≥ 2026/4/14、かつ < 65 歳前日 2051/4/14
* - 2051/3
  - TRUE
  - まだ 65 歳前日(2051/4/14)を超えていない
* - 2051/4
  - **FALSE**
  - 月末 2051/4/30 ≥ 65 歳前日 2051/4/14 → 終了
```

(kenpo-rate-dynamic)=
## 健保適用料率の動的合算

L 列で介護該当を見て分岐します。

```{code-block} text
=G2 + IF(D2, H2, 0)
```

- `D2 = TRUE` なら `健保(介護なし) + 介護料率`
- `D2 = FALSE` なら `健保(介護なし)` のみ

これにより、**料率マスタには分離した値を持ったまま**、月次の適用料率を年齢で自動切替できます。

## 料率参照(XLOOKUP)

各料率は適用開始日が変わるため、月次計算行から「対象月以下で最も新しい開始日」のレコードを引きます。

```{code-block} text
=XLOOKUP(DATE(A2,B2,1), 料率マスタ!$A:$A, 料率マスタ!$B:$B, , -1, -1)
```

引数:

```{list-table}
:header-rows: 1

* - 引数
  - 値
  - 意味
* - 第 1
  - `DATE(A2,B2,1)`
  - 対象月の月初日
* - 第 2
  - `料率マスタ!$A:$A`
  - 適用開始日列
* - 第 3
  - `料率マスタ!$B:$B`
  - 健保(介護なし)料率列(他の料率は $C:$C, $D:$D, ...)
* - 第 4
  - 省略
  - 見つからないとき(空文字や規定値) → 省略すると #N/A
* - 第 5
  - `-1`
  - 一致または「次に小さい(=直前)」を返す
* - 第 6
  - `-1`
  - **末尾から検索**(降順検索)。料率マスタは時系列(昇順)なので末尾から探すと最新一致が早い
```

これで料率マスタに 1 行追加するだけで、新しい適用開始日以降の月次計算が自動で新料率に切り替わります。

## 全体の納付額が成立する論理

社員側の総額 X = `Q + R + S`、事業主側の総額 Y = `T + U + V + W`。

```{math}
\begin{align}
X + Y &= (Q + T) + (R + U) + V + (S + W) \\
      &= ROUNDDOWN(健保) + ROUNDDOWN(厚年) + 拠出金 + ROUNDDOWN(支援金) \\
      &= 通知額
\end{align}
```

各保険料の社員 + 事業主が `ROUNDDOWN(全額)` に等しい(残額方式の保証)ため、Z 列(納付額)は**常に通知額と一致**します。

検証スクリプトでは 254 ケース(介護 ON/OFF × 127 ヶ月)すべてでこの等式が成立することを確認済みです。
