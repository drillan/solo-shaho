## 0. 背景と目的

Web アプリは `localStorage` をデータの実保存先とし、CSV エクスポート/インポートでバックアップ・復元を提供している。しかし現行ドキュメントは次の 2 点が明確に伝わらない構成になっている。

1. **保存場所が `localStorage` であること**(技術用語としては図に登場するが、利用者が「自分のデータがどこに置かれているか」を読み取れる箇所がない)
2. **`localStorage` が揮発する可能性があり、CSV をアプリ外部に保管しないと過去の入力が失われること**(現行は CSV を「可搬性」「バックアップ機能」として肯定的にのみ紹介し、揮発リスクへの言及がない)

本タスクで、揮発リスクと推奨運用を 1 ページに集約した専用ページを新設し、関連既存ドキュメントから導線を張る。

### 2.3 セクション 1: 保存される情報 — 詳細

- `localStorage` キー名: `solo-shaho-state`(`web/src/lib/stores/appState.ts` で定義された定数)
- 保存対象を表で示す:

| データ種別 | 保存される | 備考 |
|---|---|---|
| プロフィール(氏名・生年月日) | ✅ | 設定タブで入力した値 |
| 報酬改定履歴(適用開始日・標準報酬月額・給与額面) | ✅ | 設定タブで管理する全行 |
| 月次メモ(通知額など) | ✅ | 月次タブで入力した値 |
| 計算結果(社員/事業主負担・納付総額・差引支給額) | ❌ | 派生値のため、毎回再計算で求める |

- 保存形式: アプリ全状態をシリアライズした JSON 1 件
- 配信ドメイン単位で分離されるため、別ドメイン版や別ホスティング先からは参照不可

### 2.4 セクション 2: データが消える契機 — 詳細

冒頭に admonition:

```{admonition} 重要
:class: warning
localStorage に保存されたデータは、ブラウザ操作・端末変更・自動削除など複数の要因で予告なく消えることがあります。
**CSV エクスポートしたファイルをアプリの外部(クラウドストレージや別フォルダ等)に保管する習慣** を持たないと、過去の入力が完全に失われます。
```

その後に表:

| 契機 | 影響 | CSV による復元 |
|---|---|---|
| ブラウザ設定でサイトデータを削除 | 全消失 | ✅ 直近のエクスポート時点まで復元可 |
| シークレット/プライベートモードで使用 | セッション終了で消失 | ⚠ 利用前の import が必須 |
| Safari の ITP による自動削除(7 日間アクセスがない場合) | 全消失 | ✅ 復元可だが運用に注意 |
| デバイス変更・OS 再インストール | 全消失 | ✅ CSV を別保管していれば復元可 |
| 異なるブラウザ間(Chrome ↔ Firefox 等) | 同期されない | ✅ CSV で移行可 |
| ブラウザのキャッシュ自動削除設定が有効 | タイミングにより消失 | ✅ 復元可だが頻度に注意 |

### 2.5 セクション 3: CSV エクスポートで防ぐ — 詳細

ポイント:

- エクスポート機能は「ボタンを押した瞬間にダウンロード」するだけで、ファイルが残るかどうかは利用者の運用次第
- ファイル名にタイムスタンプを含めて複数世代を保管する(直近 1 件だけだと、上書き保存ミスで全滅する)
- クラウドストレージ(Google Drive・iCloud・Dropbox 等)・社内ファイルサーバ・Git リポジトリ等に置く
- 推奨頻度: **月次計算を行うたびに毎回エクスポート**(設定タブを変更したときも忘れずに)

### 2.6 セクション 4: シークレット/プライベートモード使用時の注意 — 詳細

- セッション終了でブラウザが localStorage を破棄するため、計算結果や入力値が永続化されない
- 「他人のデバイスで一時的に使う」「機微データを端末に残したくない」といった用途を想定
- 運用パターン: 利用開始時に CSV インポート、終了時に最新 CSV をエクスポートして自分の保管先へ持ち帰る

### 2.7 セクション 5: 復元手順 — 詳細

1. 復元先のブラウザでアプリ配信 URL を開く
2. 右上の I/O メニューから「CSV インポート」を選択
3. 保管しておいた CSV ファイルを指定
4. 設定タブ・履歴タブで値が復元されていることを確認
5. 月次タブで対象年月を選択 → 計算結果は派生値のため自動で再計算される

## 4. 文体方針

- CLAUDE.md の natural-writing スキル方針に準拠(です・ます調、平易な日本語)
- 警告は「事実 → 影響 → 対策」の 3 点セットで簡潔に
- 既存ドキュメントの admonition 用法(MyST の `{note}` `{warning}` `{important}`)に倣う
- 技術用語は初出時に軽く補足(例: 「`localStorage`(ブラウザ内のデータ保管領域)」)
- 過度な強調(太字の濫用や絵文字)は避ける

## 6. 設計上の判断ポイント

### 6.1 専用ページを設けた理由

リスクと運用方針が散在すると「結局自分は何をすればよいか」が読み取れない。専用ページで通読できる動線を確保することを優先した。代替案として「各ページに admonition を散らす」「警告ボックスを `index.md` 冒頭に置く」も検討したが、警告だけが目立ちプライバシー優位の魅力訴求が薄まるリスクがあるため不採用。

### 6.2 `storage.md` の配置位置を `usage.md` と `csv.md` の間にした理由

利用者の認知順序に合わせる。「使い方を覚える(usage)」 → 「データがどこに保存されるかを知る(storage)」 → 「バックアップファイルの中身が必要なら詳細を読む(csv)」 という流れが自然。

### 6.3 README からは詳細を docs に誘導する方針

README に揮発契機の表まで載せると README が肥大化する。README には警告 1 行 + 詳細リンクに留め、解説本体は Sphinx ドキュメント側に集約する。
